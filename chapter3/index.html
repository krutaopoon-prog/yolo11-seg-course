บทที่ 3 Loss และ Gradient Descent

โมเดล "เรียนรู้" ได้อย่างไร: วัดว่าผิดแค่ไหน แล้วเดินลงเขาทีละก้าว

🎯 วัตถุประสงค์การเรียนรู้ เมื่อจบบทนี้ คุณควรทำสิ่งต่อไปนี้ได้
  1. อธิบายได้ว่า loss คือตัวเลขที่บอกว่าโมเดลผิดมากแค่ไหน และคำนวณ MSE ของข้อมูลชุดเล็ก ๆ ได้
  2. อธิบายได้ว่าทำไม BCE ลงโทษคำตอบที่ "ผิดแบบมั่นใจ" หนักมาก
  3. อธิบาย gradient ว่าเป็นทิศที่ loss เพิ่มเร็วที่สุด และคำนวณการปรับค่า w ← w − η·∂L/∂w หนึ่งก้าวได้
  4. อธิบายผลของ learning rate ที่เล็กไป พอดี และใหญ่ไปได้
  5. อธิบายแนวคิดของ SGD, Momentum, Adam/AdamW และบอกได้ว่า YOLO11 เลือก optimizer อย่างไร

ทบทวนความรู้เดิม

ในซิม 2.1 คุณปรับ w₁, w₂, b ด้วยมือ จนเส้นแบ่งแยกแอปเปิลแดงออกจากแอปเปิลเขียวได้ ซึ่งมีตัวเลขให้ปรับแค่ 3 ตัว แต่ yolo11n-seg มี weight และ bias 2,876,848 ตัว ปรับด้วยมือไม่ได้แน่นอน คอมพิวเตอร์จึงต้องมีของสองอย่าง อย่างแรกคือ ตัวเลขตัวเดียวที่บอกว่าตอนนี้ผิดมากแค่ไหน เรียกว่า loss อย่างที่สองคือ วิธีรู้ว่าควรขยับตัวเลขแต่ละตัวไปทางไหน ซึ่งได้จาก gradient ตอนท้ายบท คุณจะได้เห็นนิวรอนจากบทที่ 2 ปรับ w₁, w₂, b เองโดยไม่ต้องแตะ slider เลย

3.1 Loss: ตัวเลขตัวเดียวที่บอกว่าผิดแค่ไหน

ฟังก์ชันสูญเสีย (loss function) รับคำทำนายของโมเดลกับคำตอบจริง (เฉลย) แล้วให้ตัวเลขหนึ่งตัว ตัวเลขยิ่งน้อยแปลว่าทำนายยิ่งใกล้เฉลย ถ้าเท่ากับ 0 แปลว่าตรงทุกข้อ เป้าหมายของการเทรนจึงมีข้อเดียวคือ ทำให้ loss ต่ำที่สุด

MSE: สำหรับทำนาย "ตัวเลข"

เมื่อคำตอบเป็นตัวเลขต่อเนื่อง (งาน regression) เช่น ความกว้างของกล่องรอบวัตถุ ค่าที่นิยมใช้คือ Mean Squared Error (MSE) ซึ่งคำนวณ 3 ขั้น: หาความคลาดเคลื่อน (ทำนาย − จริง), ยกกำลังสอง, แล้วเฉลี่ย 

MSE = ( e₁² + e₂² + … + eₙ² ) / n        โดย eᵢ = ทำนายᵢ − จริงᵢ

ตัวอย่าง: ทำนาย 2, 4, 5 แต่ค่าจริงคือ 3, 2, 5 → ความคลาดเคลื่อน −1, 2, 0 → ยกกำลังสอง 1, 4, 0 → MSE = 5/3 ≈ 1.67

ที่ต้องยกกำลังสองมีเหตุผลสองข้อ ข้อแรก ค่าลบกับค่าบวกจะได้ไม่หักล้างกัน (−1 กับ +1 ไม่กลายเป็น "ผิด 0") ข้อสอง ความผิดก้อนใหญ่ถูกลงโทษหนักกว่า ผิด 2 ได้ 4 แต่ผิด 1 ได้แค่ 1 ในเชิงภาพ e² ก็คือ พื้นที่ของสี่เหลี่ยมจัตุรัส ที่มีด้านยาวเท่ากับความคลาดเคลื่อน ลองดูในซิมด้านล่าง

ซิมมูเลชั่น 3.1 ฟิตเส้นตรงด้วยมือ และแผนที่ของ loss

ลองปรับความชัน (m) และจุดตัดแกน (c) ให้สี่เหลี่ยมสีแดงเล็กที่สุด แล้วสังเกตว่าจุดชมพูบนแผนที่ด้านขวาขยับเข้าใกล้ ★ หรือไม่

ข้อมูลและเส้น y = m·x + c

แผนที่ loss (แต่ละจุดคือเส้นหนึ่งเส้น สีเข้ม = MSE ต่ำ) คลิกเพื่อเลือก m, c

👀 สิ่งที่ควรสังเกต
  • MSE คือ พื้นที่เฉลี่ย ของสี่เหลี่ยมสีแดง จุดที่อยู่ห่างเส้นมากสร้างสี่เหลี่ยมใหญ่มาก (ระยะ 2 เท่า พื้นที่ 4 เท่า) เส้นจึงถูกดึงเข้าหาจุดที่อยู่ไกลก่อน
  • เส้นแต่ละเส้นคือจุด หนึ่งจุด บนแผนที่ (m, c) การหาเส้นที่ดีที่สุดจึงเท่ากับการหา "ก้นหุบ" ที่ลึกที่สุดของแผนที่นี้ (★)
  • หุบมีรูปทรงรีและเอียง ขยับ m นิดเดียว loss เปลี่ยนมาก แต่ต้องขยับ c มากกว่าจึงจะเห็นผล ข้อนี้สำคัญในหัวข้อ 3.4
  • ในโมเดลจริง แผนที่มีมิติเท่ากับจำนวน parameter (เกือบ 3 ล้านมิติสำหรับ yolo11n-seg) วาดไม่ได้ แต่หลักการเหมือนกันทุกอย่าง

BCE: สำหรับทำนาย "ใช่หรือไม่ใช่"

เมื่อคำตอบเป็นใช่ (y = 1) หรือไม่ใช่ (y = 0) และโมเดลตอบเป็นความมั่นใจ p ระหว่าง 0–1 (เช่นผลจาก sigmoid ในบทที่ 2) ค่าที่ใช้คือ Binary Cross-Entropy (BCE) 

ถ้าเฉลยคือ "ใช่"  (y = 1):  L = −ln(p)
ถ้าเฉลยคือ "ไม่ใช่" (y = 0):  L = −ln(1 − p)

ไม่ต้องจำสูตร ให้ดูรูปกราฟแทน ถ้าเฉลยคือ "ใช่" แล้วโมเดลตอบ p = 0.9 จะได้ loss แค่ 0.11 ตอบ 0.5 (ไม่แน่ใจ) ได้ 0.69 แต่ถ้าตอบ 0.01 (มั่นใจว่าไม่ใช่ ซึ่งผิด) จะได้ถึง 4.61 BCE ลงโทษความ "มั่นใจแต่ผิด" หนักมาก โมเดลจึงเรียนรู้ที่จะไม่มั่นใจเกินเหตุ

รูปที่ 3.1 (ลองเลื่อนได้) กราฟของ BCE

💡 ใน YOLO11-seg YOLO11-seg ใช้ loss ทั้งสองแบบ งานทำนาย ตัวเลข เช่น ตำแหน่งกล่อง ใช้ loss เชิงระยะ (box loss แบบ CIoU และ DFL เรียนในบทที่ 10–11) ส่วนงาน "วัตถุนี้เป็นคลาสนี้หรือไม่" ใช้ BCE (ใน source ใช้ nn.BCEWithLogitsLoss ซึ่งรวม sigmoid กับ BCE ไว้ในคำสั่งเดียว) ทุกส่วนถูกรวมเป็น loss ตัวเดียวแบบถ่วงน้ำหนัก ค่าเริ่มต้นคือ box × 7.5, seg × 7.5, cls × 0.5, dfl × 1.5

3.2 Gradient: พื้นเอียงไปทางไหน

ลองนึกภาพว่าคุณยืนอยู่บนภูเขาในหมอกหนา มองไม่เห็นหุบเขาเลย เห็นแค่ว่า พื้นใต้เท้าเอียงไปทางไหน ถ้าอยากลงไปจุดต่ำสุด ทางที่สมเหตุสมผลที่สุดคือก้าวไปทางที่พื้นลาดลง แล้วดูพื้นใหม่ แล้วก้าวอีก ทำซ้ำไปเรื่อย ๆ นี่คือ Gradient Descent โดยภูเขาคือแผนที่ loss และตำแหน่งที่ยืนคือค่า weight ปัจจุบัน

  • ความชัน (slope) หรืออนุพันธ์ ∂L/∂w บอกว่า "ถ้าขยับ w ไปทางขวานิดหนึ่ง loss จะเพิ่มขึ้นหรือลดลง และเร็วแค่ไหน" ถ้าความชันเป็นบวก แปลว่าขยับขวาแล้ว loss เพิ่ม จึงควรขยับซ้าย
  • เมื่อมี parameter หลายตัว นำความชันของแต่ละตัวมาเรียงกันเป็นเวกเตอร์ เรียกว่า gradient ซึ่งชี้ไปทางที่ loss เพิ่มขึ้นเร็วที่สุด (ขึ้นเขา)
  • เราจึงเดิน สวนทาง gradient โดยขนาดก้าวคูณด้วย learning rate (η)
w_ใหม่ = w − η × ∂L/∂w

ตัวอย่าง: w = 3, ความชัน ∂L/∂w = 2, η = 0.1 → w ใหม่ = 3 − 0.1 × 2 = 2.8 ความชันเป็นบวก w จึงลดลง ถ้าความชันเป็น −2 จะได้ w ใหม่ = 3.2

คอมพิวเตอร์หาความชันของ weight ทั้ง 2.9 ล้านตัวได้พร้อมกันในการคำนวณรอบเดียว ด้วยวิธีที่เรียกว่า backpropagation ซึ่งจะเรียนในบทที่ 4

ซิมมูเลชั่น 3.2 ลูกบอลกลิ้งลงหุบ

แบบหุบเดียว: ลองกด "เดินอัตโนมัติ" ด้วย η = 0.1, 0.5, 1.0, 1.5 และ 2.1 แล้วสังเกตว่าลูกบอลลู่เข้า แกว่ง หรือกระเด็นออก จากนั้นสลับเป็นแบบสองหุบแล้วดูว่าลูกบอลตกหุบไหน

ภูมิประเทศ:
คลิกบนกราฟเพื่อวางลูกบอลจุดเริ่มต้นใหม่
👀 สิ่งที่ควรสังเกต
  • หุบเดียว: หุบนี้ออกแบบให้ทุกก้าว "ระยะห่างจากก้นหุบ" ถูกคูณด้วย (1 − η) พอดี จึงเห็นทุกกรณีชัดเจน
    • η = 0.1: เหลือ 0.9 เท่าทุกก้าว ลู่เข้าช้า ใช้ราว 80 ก้าว
    • η = 0.5: ระยะหายไปครึ่งหนึ่งทุกก้าว เร็วขึ้นมาก
    • η = 1.0: ถึงก้นหุบในก้าวเดียว
    • η = 1.5: คูณ −0.5 เลยก้นหุบไปอีกฝั่งแล้ววกกลับ แกว่งไปมาแต่แคบลงจนลู่เข้า
    • η = 2.0: คูณ −1 แกว่งอยู่กับที่ตลอดไป
    • η > 2: แต่ละก้าวกระโดดไกลขึ้นเรื่อย ๆ จนกระเด็นออก
  • ขนาดก้าวคือ η × ความชัน ตรงที่ชันมากจึงก้าวยาว และพอใกล้ก้นหุบซึ่งเกือบราบ ก้าวก็สั้นลงเอง
  • สองหุบ (ค่าเริ่มต้น η = 0.05 เริ่มที่ w = 3.6): ลูกบอลตกลง หุบตื้นด้านขวา แล้วหยุดในราว 70 ก้าว เพราะที่ก้นหุบความชันเป็น 0 จึงไม่รู้ว่ามีหุบที่ลึกกว่าอยู่ทางซ้าย อาการนี้เรียกว่าติด จุดต่ำสุดเฉพาะที่ (local minimum) แต่ถ้าคลิกเริ่มทางซ้าย จะลงหุบลึกทันที
  • สองหุบ + เปิด Momentum (เริ่มที่จุดเดิม): ลูกบอลสะสม "แรงเฉื่อย" จนกลิ้งข้ามเนินไปตกหุบที่ลึกกว่า ส่วนถ้าใช้ η ใหญ่ (0.7 ขึ้นไป) ในแบบสองหุบ ลูกบอลจะกระโดดไปมาระหว่างหุบแบบคาดเดาไม่ได้

3.3 Learning rate: ขนาดก้าวคือทุกอย่าง

learning rate เป็นค่าที่ คนตั้ง ไม่ได้เรียนรู้เอง ค่าแบบนี้เรียกว่า ไฮเปอร์พารามิเตอร์ (hyperparameter) ซิม 3.2 แสดงให้เห็นแล้วว่ามันกำหนดว่าการเทรนจะสำเร็จหรือพัง

ηสิ่งที่เห็นอาการบนกราฟ loss ตอนเทรนจริง
เล็กไปก้าวสั้น ลงหุบช้ามากloss ลดลงช้า ๆ เกือบเป็นเส้นตรง เทรนจนจบก็ยังไม่ต่ำพอ
พอดีลงหุบเร็วแล้วนิ่งloss ลดลงเร็วช่วงแรก แล้วค่อย ๆ ราบลง
ใหญ่ไปกระโดดข้ามก้นหุบไปมาloss แกว่งขึ้นลง ไม่ลงต่ำสุด
ใหญ่มากกระเด็นออกloss พุ่งขึ้นจนเป็น nan (ตัวเลขพัง)

ในทางปฏิบัติ จึงมักเริ่มด้วย η ปานกลาง แล้วค่อย ๆ ลดลงเมื่อใกล้ก้นหุบ (learning rate schedule) และช่วงแรกสุดจะค่อย ๆ เพิ่มจากค่าน้อย ๆ (warmup) YOLO11 ทำทั้งสองอย่าง ซึ่งจะดูรายละเอียดในบทที่ 11

3.4 Optimizer: วิธีก้าวที่ฉลาดขึ้น

สูตร w − η·∂L/∂w เป็นแบบพื้นฐานที่สุด ยังมีวิธีปรับปรุงการก้าวให้ดีขึ้นอีกหลายแบบ แต่ละแบบเรียกว่า optimizer

  • SGD (Stochastic Gradient Descent) คือสูตรพื้นฐาน คำว่า stochastic (สุ่ม) หมายความว่าแต่ละก้าวคำนวณความชันจากข้อมูลเพียงกลุ่มเล็ก ๆ (batch) ไม่ใช่ทั้งชุด จึงเร็วแต่ทิศมีความแกว่งเล็กน้อย (บทที่ 4)
  • Momentum ใส่ "แรงเฉื่อย" ให้ก้าว โดยนำทิศของก้าวก่อน ๆ มาสะสม ทิศที่ชี้ไปทางเดิมสม่ำเสมอจะเร่งขึ้น ส่วนทิศที่สลับไปมา (ซิกแซก) จะหักล้างกันเอง
  • Adam ปรับขนาดก้าวของ แต่ละ parameter แยกกัน parameter ที่ความชันใหญ่สม่ำเสมอจะถูกย่อก้าวลง ส่วนที่ความชันเล็กจะถูกขยายก้าว ทุกตัวจึงเดินได้พอ ๆ กันแม้หุบจะรีและเอียง (และมี momentum ในตัว)
  • AdamW คือ Adam ที่แยกการทำ weight decay (ดึง weight ให้เข้าใกล้ 0 ทีละนิดเพื่อไม่ให้โตเกินไป) ออกมาจากการคำนวณก้าว ทำให้ได้ผลดีกว่าเดิม

ซิมด้านล่างใช้แผนที่ loss เดียวกับซิม 3.1 แต่ให้คอมพิวเตอร์เป็นคนเดินแทนคุณ

ซิมมูเลชั่น 3.3 ให้คอมพิวเตอร์หาเส้นเอง

ลองกด "เดินอัตโนมัติ" ด้วย SGD แล้วดูเส้นทางบนแผนที่ จากนั้นรีเซ็ตและลอง Momentum กับ Adam แล้วสังเกตว่าแบบไหนถึง ★ ได้ในจำนวนก้าวน้อยที่สุด

optimizer:

แผนที่ loss: ลูกศรแดง = gradient (ขึ้นเขา) · ลูกศรน้ำเงิน = ทิศลงเร็วที่สุด · คลิกเพื่อเปลี่ยนจุดเริ่ม

loss ตามจำนวนก้าว (แกนตั้งแบบลอการิทึม)

👀 สิ่งที่ควรสังเกต
  • SGD: ลูกศรน้ำเงินไม่ได้ชี้ไปที่ ★ ตรง ๆ แต่ชี้ลงหน้าผาที่ชันที่สุด เส้นทางจึงพุ่งลงหุบก่อน แล้วค่อย ๆ คืบไปตามท้องหุบที่เกือบราบ ใช้หลายร้อยก้าว
  • SGD กับ η = 0.2 ขึ้นไป: เส้นทางกระโดดข้ามหุบไปมาแล้วกระเด็นออก เหมือนลูกบอลในซิม 3.2
  • Momentum: ความเร็วสะสมตามท้องหุบ จึงถึง ★ เร็วกว่ามาก แต่อาจเลยไปแล้ววกกลับ
  • Adam: ก้าวของ m และ c มีขนาดพอ ๆ กันตั้งแต่แรก แม้หุบจะรีมาก จึงเดินค่อนข้างตรงไปยัง ★

3.5 ปิดท้าย: นิวรอนในบทที่ 2 เรียนรู้เอง

ตอนนี้มีครบทุกชิ้นแล้ว ได้แก่ นิวรอน (บทที่ 2), BCE ที่วัดว่าทำนายผิดแค่ไหน และ gradient descent ที่บอกว่าควรปรับ w₁, w₂, b ไปทางไหน ซิมด้านล่างเริ่มจากเส้นแบ่งเดียวกับค่าเริ่มต้นของซิม 2.1 แต่คราวนี้คอมพิวเตอร์ปรับเอง

👀 สิ่งที่ควรสังเกต
  • ขนาดของจุดแต่ละจุดเท่ากับ BCE ของพิกเซลนั้น จุดที่ทำนายผิดแบบมั่นใจจึงใหญ่ที่สุด และเป็นตัวที่ "ดึง" เส้นแรงที่สุด
  • โจทย์แอปเปิล: พอแยกได้ครบแล้ว เส้นแทบไม่ขยับ แต่ w₁, w₂, b ยังโตขึ้นเรื่อย ๆ เพราะการคูณ w ให้ใหญ่ขึ้นทำให้มั่นใจขึ้นและ BCE ลดลงอีก (สีพื้นหลังคมขึ้น) weight decay ใน AdamW และ YOLO11 มีไว้ยั้งอาการนี้
  • โจทย์ส้ม (Momentum): loss ลดลงแล้วค้างที่ประมาณ 0.59 ทำนายถูกราว 49 จาก 70 ไม่ถึง 70/70 เพราะนิวรอนเดียวสร้างได้แค่เส้นตรงเส้นเดียว (บทที่ 2) gradient descent หาจุดที่ดีที่สุดเท่าที่โครงสร้างจะทำได้ แต่ทำเกินขีดจำกัดของโครงสร้างไม่ได้
  • สังเกตว่า 49/70 น้อยกว่าเส้นที่ดีที่สุดที่หาได้ด้วยมือ (56/70) ด้วยซ้ำ เพราะ gradient descent ทำให้ BCE ต่ำที่สุด ไม่ได้นับจำนวนข้อที่ถูกโดยตรง สิ่งที่ถูก optimize คือ loss เสมอ
  • โจทย์ส้มแล้วสลับเป็น SGD: ต้องใช้ราว 13,000 ครั้งกว่าจะถึงจุดเดียวกัน (Momentum ใช้ราว 1,000 ครั้ง และซิมนี้หยุดที่ 4,000 ครั้ง) เพราะค่า R ของทุกจุดเกือบเท่ากัน (0.75–0.98) หุบของ loss จึงรีและยาวมาก เหมือนที่เห็นในซิม 3.3
  • ลอง η = 30 กับโจทย์ส้ม การปรับแต่ละครั้งกระโดดไกลเกินไป เส้นสะบัดไปมาและ loss ขึ้นลงไม่นิ่ง

3.6 ใน YOLO11 จริง

ตรวจจาก source และจากการเทรนจริงบน coco8-seg 2 epoch (ultralytics 8.4.2) ได้ข้อเท็จจริงดังนี้

  • loss ที่บันทึกทุก epoch อยู่ในไฟล์ results.csv มี 5 คอลัมน์ฝั่งเทรน: train/box_loss, train/seg_loss, train/cls_loss, train/dfl_loss และ train/sem_loss (สำหรับ yolo11-seg คอลัมน์ sem_loss เป็น 0 เสมอ เพราะใช้กับโมเดลที่มีสาขา semantic segmentation เท่านั้น) และมีชุดเดียวกันฝั่ง val/
  • ค่าเริ่มต้น lr0 = 0.01, momentum = 0.937, weight_decay = 0.0005, optimizer = auto
  • แต่เมื่อ optimizer = auto Ultralytics จะ ไม่ใช้ lr0 และ momentum ที่ตั้งไว้ แล้วเลือกเองตามจำนวนก้าวทั้งหมดของการเทรน
    จำนวนก้าว = ⌈จำนวนภาพ / max(batch, 64)⌉ × epochsoptimizer ที่เลือกlearning rate
    มากกว่า 10,000 (ชุดข้อมูลใหญ่)SGD (momentum 0.9, Nesterov)0.01
    ไม่เกิน 10,000 (ชุดข้อมูลเล็ก)MuSGD (momentum 0.9)0.002 × 5 / (4 + จำนวนคลาส)
    ตอนเทรน coco8-seg (80 คลาส) log พิมพ์ว่า MuSGD(lr=0.000119, momentum=0.9) ซึ่งตรงกับ 0.01 / 84 = 0.000119
  • MuSGD เป็น optimizer ใหม่ใน Ultralytics ที่ผสมการอัปเดตแบบ SGD with momentum เข้ากับวิธีชื่อ Muon แนวคิดหลักยังเป็น "สะสมทิศ (momentum) แล้วก้าวสวนทาง gradient" เหมือนในบทนี้ รายละเอียดของ Muon อยู่นอกขอบเขตรายวิชา
  • weight decay ใช้กับ weight ทั่วไปเท่านั้น ไม่ใช้กับ bias และ weight ของ BatchNorm (เห็นในโค้ดที่แบ่ง parameter เป็นกลุ่ม)

🔗 อยู่ตรงไหนใน YOLO11-seg

loss และ gradient descent ไม่ได้อยู่บนเส้นทางตอน ทำนาย แต่อยู่ในวงจร เทรน ตอนเทรน เอาต์พุตของ Head ถูกนำไปเทียบกับเฉลยเพื่อคำนวณ loss (box, seg, cls, dfl) แล้ว gradient ไหลย้อนกลับไปปรับ weight ทุกตัวใน Backbone, Neck และ Head (บทที่ 4) ค่าที่คุณกำหนดตอนสั่งเทรน เช่น lr0 และ optimizer คือขนาดก้าวและวิธีก้าวในบทนี้ และตัวเลข loss ที่ Ultralytics พิมพ์ทุก epoch ก็คือความสูงของจุดที่โมเดลยืนอยู่บนแผนที่ loss

สรุปท้ายบท

  • Loss คือตัวเลขตัวเดียวที่บอกว่าทำนายผิดแค่ไหน การเทรนคือการทำให้ loss ต่ำที่สุด
  • MSE = ค่าเฉลี่ยของ (ทำนาย − จริง)² ใช้กับการทำนายตัวเลข ส่วน BCE = −ln(p) หรือ −ln(1 − p) ใช้กับใช่/ไม่ใช่ และลงโทษความมั่นใจที่ผิดหนักมาก
  • Gradient คือเวกเตอร์ของความชันที่ชี้ไปทางที่ loss เพิ่มเร็วที่สุด จึงปรับด้วย w ← w − η·∂L/∂w
  • Learning rate เล็กไปทำให้ช้า ใหญ่ไปทำให้แกว่งหรือพัง และ gradient descent อาจติดหุบตื้น (local minimum)
  • Momentum สะสมแรงเฉื่อย ส่วน Adam ปรับขนาดก้าวแยกตาม parameter และ AdamW แยก weight decay ออกมา
  • YOLO11 ใช้ BCE กับคลาส และเมื่อ optimizer = auto จะเลือก SGD (lr 0.01) สำหรับการเทรนยาว หรือ MuSGD (lr = 0.01/(4 + nc)) สำหรับการเทรนสั้น โดยไม่ใช้ lr0 ที่ตั้งไว้
