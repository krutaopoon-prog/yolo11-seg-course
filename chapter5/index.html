บทที่ 5 Convolution

หน้าต่างเล็ก ๆ ที่เลื่อนไปทั่วภาพ: ชิ้นส่วนพื้นฐานที่สุดของ YOLO11

🎯 วัตถุประสงค์การเรียนรู้ เมื่อจบบทนี้ คุณควรทำสิ่งต่อไปนี้ได้
  1. อธิบายการเลื่อน kernel ไปบนภาพ และคำนวณผลรวมของผลคูณที่ตำแหน่งหนึ่งได้
  2. คำนวณขนาดเอาต์พุตด้วยสูตร O = ⌊(I + 2P − K) / S⌋ + 1 ได้ และอธิบายผลของ stride กับ padding ได้
  3. อธิบาย convolution หลายช่อง (multi-channel) และคำนวณจำนวนพารามิเตอร์ K × K × Cin × Cout (+ bias) ได้
  4. อธิบายได้ว่า kernel ในโครงข่ายจริงได้มาจากการเรียนรู้ และอ่านความหมายของชั้น Conv ชั้นแรกของ YOLO11 ได้

ทบทวนความรู้เดิม

ในบทที่ 2 นิวรอนหนึ่งตัวคำนวณ ผลรวมของ (weight × อินพุต) + bias แล้วผ่าน activation และในบทที่ 3–4 weight เหล่านี้ถูกปรับด้วย gradient descent และ backpropagation ถ้าเอานิวรอนแบบนั้นมารับภาพ 640 × 640 × 3 ตรง ๆ นิวรอน ตัวเดียว ต้องมี weight 1,228,800 ตัว (หนึ่งตัวต่อหนึ่งตัวเลขในภาพ, บทที่ 1) และนิวรอนที่เรียนรู้ว่า "แอปเปิลอยู่มุมซ้ายบน" ก็ไม่รู้จักแอปเปิลที่อยู่มุมขวาล่าง ต้องเรียนใหม่ทุกตำแหน่ง Convolution แก้ทั้งสองปัญหาด้วยความคิดง่าย ๆ คือ ใช้นิวรอนที่มองแค่ หน้าต่างเล็ก ๆ แล้วเลื่อนนิวรอนตัวเดิม (weight ชุดเดิม) ไปทั่วทั้งภาพ

5.1 Kernel เลื่อนไปทีละช่อง

kernel (หรือ filter) คือตาราง weight ขนาดเล็ก เช่น 3 × 3 การทำ convolution มีขั้นตอนดังนี้

  1. วาง kernel ทับบนภาพที่มุมซ้ายบน
  2. คูณตัวเลขที่ทับกันทีละคู่ (9 คู่สำหรับ 3 × 3) แล้วบวกรวมกัน ได้ตัวเลข 1 ตัว
  3. เขียนตัวเลขนั้นลงในตารางผลลัพธ์ แล้วเลื่อน kernel ไปทางขวา ทำซ้ำจนครบทั้งภาพ

ตารางผลลัพธ์เรียกว่า feature map ตัวเลขแต่ละช่องบอกว่า "ตรงตำแหน่งนี้ ภาพมีลวดลายแบบที่ kernel มองหามากแค่ไหน" เพราะผลรวมของผลคูณจะใหญ่เมื่อภาพใต้หน้าต่างมีรูปแบบเหมือน kernel (ค่าบวกตรงค่าสว่าง ค่าลบตรงค่ามืด) 

หน้าต่างภาพ        kernel (ขอบแนวตั้ง)
0  0  9            −1  0  1
0  0  9      ×     −1  0  1      →  0·(−1)+0·0+9·1 + 0·(−1)+0·0+9·1 + 0·(−1)+0·0+9·1 = 27
0  0  9            −1  0  1

หมายเหตุ: ในคณิตศาสตร์ convolution แท้จะกลับด้าน kernel ก่อนคูณ แต่ใน deep learning (รวมถึง nn.Conv2d ของ PyTorch) ไม่กลับด้าน ซึ่งในทางเทคนิคเรียกว่า cross-correlation แต่ทุกคนเรียกว่า convolution และเมื่อ kernel ถูกเรียนรู้อยู่แล้ว การกลับหรือไม่กลับก็ไม่มีผลต่อความสามารถ

ซิมมูเลชั่น 5.1 เลื่อน kernel ทีละช่อง

ลองกด "ก้าวถัดไป" แล้วดูการคูณและบวกในกล่องด้านล่าง จากนั้นเปลี่ยน stride และ padding แล้วสังเกตว่าตารางผลลัพธ์เปลี่ยนขนาดตามสูตรอย่างไร

👀 สิ่งที่ควรสังเกต
  • ภาพขอบแนวตั้ง + kernel ขอบแนวตั้ง: ผลลัพธ์เป็น 27 (แดง) ตรงคอลัมน์ที่หน้าต่างคร่อมรอยต่อมืด→สว่าง และเป็น 0 ในบริเวณที่สีเรียบ ไม่ว่าจะมืดล้วนหรือสว่างล้วน kernel นี้จึง "ตรวจจับขอบ" ไม่ได้ตรวจจับความสว่าง
  • ภาพเดิมแต่เปลี่ยนเป็น kernel ขอบแนวนอน: ผลลัพธ์เป็น 0 ทุกช่อง เพราะในภาพไม่มีขอบแนวนอนเลย (เมื่อ P = 0) kernel แต่ละตัวมองหาลวดลายของตัวเองเท่านั้น
  • ภาพสี่เหลี่ยมสว่าง + kernel ขอบแนวตั้ง: ขอบซ้ายของสี่เหลี่ยมได้ค่าบวก (แดง) ขอบขวาได้ค่าลบ (น้ำเงิน) เครื่องหมายบอกทิศของขอบ
  • S = 1, P = 0 ได้ 5 × 5 · S = 1, P = 1 ได้ 7 × 7 เท่าเดิม · S = 2, P = 1 ได้ 4 × 4 (เกือบครึ่ง) ตรงกับสูตรทุกกรณี
  • เปิด P = 1 กับภาพขอบแนวตั้ง: คอลัมน์ขวาสุดของผลลัพธ์กลายเป็นค่าลบ เพราะ kernel เห็นขอบปลอมระหว่างภาพสว่าง (9) กับขอบเติมศูนย์ (0) นี่คือผลข้างเคียงของ zero padding ที่ขอบภาพ

5.2 Stride, Padding และขนาดของ feature map

  • stride (S) คือระยะที่ kernel เลื่อนแต่ละครั้ง S = 1 เลื่อนทีละช่อง S = 2 ข้ามทีละ 2 ช่อง ทำให้ feature map เล็กลงประมาณครึ่งหนึ่งในแต่ละด้าน
  • padding (P) คือการเติมขอบรอบภาพ (ปกติเติม 0) จำนวน P ช่อง ทำให้ kernel วางคร่อมขอบภาพได้ และควบคุมไม่ให้ภาพหดลง
O = ⌊ (I + 2P − K) / S ⌋ + 1        I = ขนาดอินพุต, K = ขนาด kernel, ⌊ ⌋ = ปัดลง

7 × 7, K = 3, S = 1, P = 0  →  (7 + 0 − 3)/1 + 1 = 5
7 × 7, K = 3, S = 1, P = 1  →  (7 + 2 − 3)/1 + 1 = 7      (ขนาดเท่าเดิม)
7 × 7, K = 3, S = 2, P = 1  →  ⌊(7 + 2 − 3)/2⌋ + 1 = 4
640,   K = 3, S = 2, P = 1  →  ⌊639/2⌋ + 1 = 319 + 1 = 320   ← ชั้นแรกของ YOLO11

ที่มาของสูตร: หลังเติมขอบ ภาพกว้าง I + 2P ช่อง kernel กว้าง K ช่องจึงวางได้ที่ตำแหน่งแรก แล้วเหลือที่ให้เลื่อน I + 2P − K ช่อง เลื่อนครั้งละ S ช่องได้ ⌊(I + 2P − K)/S⌋ ครั้ง บวกตำแหน่งแรกอีก 1

💡 ใน YOLO11 บล็อก Conv ของ Ultralytics (nn/modules/conv.py) คำนวณ padding อัตโนมัติด้วยฟังก์ชัน autopad ซึ่งได้ P = K // 2 (หารปัดลง) kernel 3 จึงได้ P = 1 เสมอ ผลคือ Conv ที่ stride 1 รักษาขนาดภาพไว้ และ Conv ที่ stride 2 ลดขนาดลงครึ่งหนึ่งพอดี (640 → 320 → 160 → …)

5.3 Kernel ตัวอย่าง: ขอบ เบลอ และความคม

ก่อนยุค deep learning คนออกแบบ kernel ด้วยมือเพื่อประมวลผลภาพ ตัวอย่างที่นิยมได้แก่ kernel ตรวจขอบ (ค่าบวกด้านหนึ่ง ค่าลบอีกด้าน ผลรวมเป็น 0) kernel เบลอ (เฉลี่ยเพื่อนบ้าน) และ kernel เพิ่มความคม (ขยายความต่างระหว่างจุดกลางกับเพื่อนบ้าน) ลองใช้กับภาพผลไม้ประจำวิชา

ซิมมูเลชั่น 5.2 กรองภาพผลไม้ด้วย kernel

ลองเลือก kernel ขอบแนวตั้งกับขอบแนวนอน แล้วเทียบว่าขอบส่วนไหนของตะกร้าเด่นขึ้น จากนั้นลองแก้ตัวเลขใน kernel เองแล้วดูผล

👀 สิ่งที่ควรสังเกต
  • ขอบแนวตั้ง: ซี่ตะกร้าที่เอียงลงและขอบซ้ายขวาของผลไม้เด่น แต่ลายสานแนวนอนและขอบโต๊ะหายไปเกือบหมด · ขอบแนวนอน: กลับกัน ขอบโต๊ะ ปากตะกร้า และลายสานแนวนอนเด่นขึ้นมาแทน
  • สีแดงกับสีน้ำเงินบอกทิศ: แดง = มืด→สว่างเมื่อมองไปทางขวา (หรือลงล่าง) น้ำเงิน = สว่าง→มืด พื้นที่สีเรียบ เช่น ผนัง ได้ค่าใกล้ 0 (ขาว)
  • เบลอ: แต่ละพิกเซลกลายเป็นค่าเฉลี่ยของ 9 พิกเซลรอบตัว รายละเอียดเล็ก ๆ (ลายสาน) จางลง · เพิ่มความคม: ขอบชัดขึ้น เพราะ 5 × กลาง − เพื่อนบ้าน 4 ตัว ขยายความต่าง
  • เส้นตรงที่ขอบซ้าย-ขวาของผลลัพธ์ขอบแนวตั้ง (หรือขอบบน-ล่างของผลลัพธ์ขอบแนวนอน) คือขอบปลอมจาก zero padding แบบเดียวกับในซิม 5.1 ลองเปลี่ยนเป็น padding 0 แล้วเส้นนี้จะหายไป (ภาพเหลือ 254 × 254)
  • stride 2: ภาพผลลัพธ์เหลือ 128 × 128 (เห็นเป็นพิกเซลใหญ่ขึ้น) ข้อมูลตำแหน่งละเอียดหายไปครึ่งหนึ่งในแต่ละด้าน แต่ลวดลายหลักยังอยู่ครบ

5.4 Convolution หลายช่อง (multi-channel)

ภาพสีมี 3 ช่อง (R, G, B) และ feature map ในชั้นลึก ๆ มีได้หลายร้อยช่อง กฎของ convolution หลายช่องมีสองข้อ

  1. kernel หนึ่งตัวมีความลึกเท่ากับจำนวนช่องอินพุต เช่น อินพุต 3 ช่อง kernel 3 × 3 จึงเป็นก้อน 3 × 3 × 3 = 27 ตัวเลข ที่แต่ละตำแหน่ง คูณ 27 คู่แล้วบวกรวมกันทั้งหมด (รวมทุกช่อง) ได้ตัวเลข ตัวเดียว
  2. จำนวน kernel = จำนวนช่องเอาต์พุต kernel แต่ละตัวสร้าง feature map ของตัวเอง 1 ช่อง มี kernel 16 ตัวก็ได้ feature map 16 ช่อง
จำนวนพารามิเตอร์ = K × K × C_in × C_out  (+ C_out ถ้ามี bias)
ตัวอย่าง: K = 3, C_in = 3, C_out = 16  →  3 × 3 × 3 × 16 = 432  (+ 16 bias = 448)

สังเกตว่าจำนวนพารามิเตอร์ ไม่ขึ้นกับขนาดภาพ เลย เพราะ kernel ชุดเดิมถูกใช้ซ้ำทุกตำแหน่ง (เรียกว่า weight sharing) ภาพ 640 × 640 หรือ 1280 × 1280 ก็ใช้ 432 ตัวเท่าเดิม ต่างกันแค่จำนวนครั้งที่คำนวณ

ซิมมูเลชั่น 5.3 Convolution หลายช่องแบบ 3 มิติ

ลองกด "▶ เล่น" แล้วดูว่า kernel ก้อนเดียวคลุมอินพุต ทุกช่อง พร้อมกัน แต่ให้ผลลัพธ์แค่ 1 ลูกบาศก์ จากนั้นกดตัวอย่าง "ชั้น 0" และ "ชั้น 1" ของ yolo11n-seg แล้วดูว่าก้อน kernel ตรงกลางโตขึ้นแค่ไหน

👀 สิ่งที่ควรสังเกต
  • กรอบชมพูบนอินพุตลึกทะลุ ทุกช่อง เสมอ (ความลึกของ kernel = Cin) แต่ผลลัพธ์ของแต่ละตำแหน่งมีแค่ 1 ลูกบาศก์ในช่องที่มีสีเดียวกับ kernel ตัวนั้น
  • kernel แต่ละตัวเติมช่องเอาต์พุตของตัวเองหนึ่งแผ่น kernel 2 ตัวได้เอาต์พุต 2 แผ่น: จำนวน kernel = Cout
  • นับลูกบาศก์ในกลุ่ม kernel ตรงกลางได้เท่ากับจำนวน weight พอดี (เริ่มต้น: 2 ก้อน × 3 × 3 × 3 = 54) ลองเปลี่ยนขนาดภาพ I แล้วดูว่ากลุ่มตรงกลางไม่เปลี่ยนเลย มีแต่อินพุตและเอาต์พุตที่เปลี่ยน
  • ชั้น 0 ของ yolo11n-seg: kernel 16 ก้อน ก้อนละ 3 × 3 × 3 = 432 weight · ชั้น 1: kernel 32 ก้อน แต่ละก้อนลึก 16 = 4,608 weight กลุ่มตรงกลางโตตาม Cin × Cout ไม่ใช่ตามขนาดภาพ
  • Conv ของ YOLO11 ไม่มี bias (bias=False) เพราะชั้นถัดไปคือ BatchNorm ซึ่งมีค่าเลื่อน (β) ของตัวเองอยู่แล้ว (BatchNorm จะเรียนในบทที่ 6)

5.5 Kernel ในโครงข่ายจริง "เรียนรู้" เอง

ใน CNN ไม่มีใครออกแบบ kernel ด้วยมือ ตัวเลขทุกตัวใน kernel คือ weight ธรรมดาที่เริ่มจากค่าสุ่ม แล้วถูกปรับด้วย gradient descent และ backpropagation (บทที่ 3–4) ให้ loss ลดลง kernel ที่ได้จึงเป็นลวดลายใดก็ได้ที่ "ช่วยงานตรวจจับ" มากที่สุด ซึ่งบางตัวคล้าย kernel ตรวจขอบที่คนออกแบบ บางตัวตอบสนองต่อสีเฉพาะ ซิมด้านล่างใช้ kernel จริงทั้ง 16 ตัว ของชั้นแรกใน yolo11n-seg.pt (ดึงด้วย tools/ch5_first_layer.py) กับภาพผลไม้ที่ผ่าน letterbox เป็น 640 × 640 แล้ว (บทที่ 1) คำนวณแบบเดียวกับโมเดลทุกขั้น: conv (stride 2, padding 1) → BatchNorm → SiLU

  • kernel 7 และ 8 คือตัวตรวจขอบแนวนอนสองทิศ ดูช่อง 8: เส้นแนวนอนสว่างที่ขอบบนของภาพ ตรงรอยต่อระหว่างขอบเทา 114 ของ letterbox กับผนัง (ค่าเฉลี่ยแถวนั้น 19.6 เทียบกับราว 1.3 ในบริเวณอื่น) โมเดลจึง "เห็น" ขอบ letterbox ด้วย
  • ตัวตรวจสี: kernel 12 (เขียว: G บวก R และ B ลบ) ให้ค่าเฉลี่ยบนแอปเปิลเขียว 17.9 กล้วย 8.6 แต่บนองุ่นและแอปเปิลแดงเกือบ 0 · kernel 15 (แดง) สูงบนแอปเปิลแดง 15.1 ส้ม 13.3 กล้วย 12.8 แต่บนองุ่นแค่ 1.1 · kernel 5 (G ลบมาก) สูงบนองุ่น 14.9 และแอปเปิลแดงลูกหน้า 10.2 kernel กลุ่มนี้ไม่สนลวดลาย แต่เปรียบเทียบช่องสีกัน
  • บางช่องแทบไม่ทำงานกับภาพนี้ เช่น ช่อง 13 มีค่าเกือบ 0 ทั้งภาพ (ภาพในช่องนี้จึงดูเป็นจุดรบกวน) ช่องเหล่านี้อาจมีประโยชน์กับภาพแบบอื่นใน COCO
  • ทั้งหมดนี้คือ "สายตาชั้นแรก" ของ YOLO11 ซึ่งแค่หาขอบ จุด และสี ส่วนการรวมเป็นรูปทรงและวัตถุเกิดในชั้นถัด ๆ ไป (บทที่ 6)

🔗 อยู่ตรงไหนใน YOLO11-seg

บรรทัดแรกของ Backbone ในไฟล์ yolo11-seg.yaml คือ [-1, 1, Conv, [64, 3, 2]] # 0-P1/2 หมายถึง Conv ที่มี kernel 3 × 3 stride 2 จำนวน 64 ช่อง ซึ่งรุ่น n คูณจำนวนช่องด้วย 0.25 จึงเหลือ 16 ช่อง พอดีกับซิม 5.4 ภาพ 640 × 640 จึงกลายเป็น feature map ขนาด 320 × 320 × 16 ตามสูตร ⌊(640 + 2 − 3)/2⌋ + 1 = 320 ป้าย P1/2 แปลว่า "ระดับที่ 1 ขนาด 1/2 ของภาพ"

ชั้นที่บรรทัดใน yamlK, S, PCin → Coutshape เอาต์พุตweight ของ conv

Conv แบบ stride 2 ห้าครั้งใน Backbone ทำให้ภาพเล็กลงทีละครึ่ง 640 → 320 → 160 → 80 → 40 → 20 ขณะที่จำนวนช่องเพิ่มขึ้นเรื่อย ๆ ซึ่งจะเป็นเรื่องหลักของบทที่ 6 ส่วน Conv แทบทุกตัวในโมเดล (รวม 90 บล็อกใน yolo11n-seg) ทำงานแบบเดียวกับในบทนี้ทุกประการ ต่างกันแค่จำนวนช่องและขนาด kernel

สรุปท้ายบท

  • Convolution คือการเลื่อน kernel ขนาดเล็กไปทั่วภาพ แต่ละตำแหน่งคูณกันทีละคู่แล้วบวกรวม ได้ feature map ที่บอกว่าลวดลายแบบ kernel อยู่ตรงไหน
  • ขนาดเอาต์พุต O = ⌊(I + 2P − K)/S⌋ + 1 · stride 2 ลดขนาดลงราวครึ่งหนึ่ง · padding ช่วยรักษาขนาดและให้ kernel คร่อมขอบภาพได้
  • kernel หนึ่งตัวลึกเท่าจำนวนช่องอินพุตและให้ผลลัพธ์ 1 ช่อง จำนวน kernel = จำนวนช่องเอาต์พุต
  • จำนวนพารามิเตอร์ = K × K × Cin × Cout (+ Cout ถ้ามี bias) ไม่ขึ้นกับขนาดภาพ เพราะใช้ kernel ชุดเดียวทุกตำแหน่ง
  • kernel ในโครงข่ายจริงเรียนรู้จาก gradient descent ไม่ได้ออกแบบด้วยมือ
  • ชั้นแรกของ YOLO11 คือ Conv K = 3, S = 2, P = 1 (autopad) ไม่มี bias ตามด้วย BatchNorm และ SiLU: (1, 3, 640, 640) → (1, 16, 320, 320) ใช้ weight 432 ตัวในรุ่น n
