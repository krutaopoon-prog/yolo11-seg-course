บทที่ 1 ภาพดิจิทัลคือตัวเลข

ก่อนจะเข้าใจว่า YOLO "คิด" อย่างไร ต้องรู้ให้แน่ชัดก่อนว่ามัน "ได้รับอะไร"

🎯 วัตถุประสงค์การเรียนรู้ เมื่อจบบทนี้ คุณควรทำสิ่งต่อไปนี้ได้
  1. อธิบายได้ว่าภาพสีหนึ่งภาพคือชุดตัวเลข 0–255 และบอก shape ได้ทั้งแบบ (H, W, C) และ (C, H, W)
  2. บอก shape ของ batch (N, C, H, W) และนับจำนวนตัวเลขในภาพหนึ่งภาพได้
  3. คำนวณค่าหลัง normalize แบบที่ Ultralytics ใช้ (หารด้วย 255) ได้
  4. คำนวณ scale และ padding ของ letterbox ได้ และอธิบายได้ว่าทำไมไม่ยืดภาพตรง ๆ
  5. แปลงพิกัดจากภาพหลัง letterbox กลับไปเป็นพิกัดบนภาพต้นฉบับได้

ทบทวนความรู้เดิม

บทนี้เป็นบทแรก จึงใช้ความรู้ที่คุณมีอยู่แล้วเพียงสองเรื่อง เรื่องแรก ถ้าซูมภาพในโทรศัพท์เข้าไปมาก ๆ จะเห็นว่าภาพประกอบด้วยสี่เหลี่ยมเล็ก ๆ สีเดียวเรียงกันเป็นตาราง เรื่องที่สองคือ ตาราง ที่มีแถวและคอลัมน์ เช่นตารางใน Excel บทนี้รวมสองเรื่องนี้เข้าด้วยกันเพื่อตอบคำถามว่า เมื่อเราส่งภาพให้ YOLO11-seg สิ่งที่มันได้รับจริง ๆ คืออะไร คำตอบคือก้อนตัวเลขขนาดใหญ่ที่จัดเรียงตามรูปแบบที่แน่นอน ก้อนตัวเลขนี้ก็คือสิ่งที่ทุกบทต่อจากนี้จะนำไปคำนวณ

1.1 พิกเซลและช่องสี RGB

ภาพดิจิทัลประกอบด้วย พิกเซล (pixel) เรียงเป็นตาราง ภาพกว้าง W พิกเซล สูง H พิกเซล ก็มีพิกเซลทั้งหมด H × W จุด แต่ละพิกเซลของภาพสีเก็บตัวเลข 3 ตัว คือความเข้มของแสง แดง (R) เขียว (G) และ น้ำเงิน (B) สีที่ตาเราเห็นเกิดจากการผสมแสงทั้งสามนี้

ไฟล์ภาพทั่วไปเก็บตัวเลขแต่ละตัวด้วย 8 บิต (8-bit) ได้ 28 = 256 ระดับ คือ 0 ถึง 255 ค่า 0 หมายถึงไม่มีแสงสีนั้นเลย และ 255 หมายถึงแสงสีนั้นเต็มที่ ในโค้ดชนิดข้อมูลนี้เรียกว่า uint8 (unsigned 8-bit integer)

ภาพสี 640 × 640 พิกเซลจึงมีตัวเลขทั้งหมด 640 × 640 × 3 = 1,228,800 ตัว ตัวละ 1 ไบต์ รวมประมาณ 1.2 MB (ไฟล์ .jpg มีขนาดเล็กกว่านี้เพราะถูกบีบอัด แต่เมื่อเปิดอ่านเข้าหน่วยความจำ ภาพจะถูกคลายกลับเป็นตัวเลขครบทุกตัว)

ซิมมูเลชั่น 1.1 ส่องพิกเซล

ลองเลื่อนเมาส์หรือแตะไปบนแอปเปิลแดง ส้ม และตะกร้า แล้วสังเกตว่าวัตถุที่ "สีเดียวกัน" มีตัวเลขเหมือนกันทุกจุดหรือไม่

ดูภาพ:   ตัวเลขในตาราง:

กรอบสีดำ = พื้นที่ 8×8 ที่ขยายให้ดูทางขวา คลิกหรือแตะเพื่อเลือกจุด

👀 สิ่งที่ควรสังเกต
  • แอปเปิลลูกเดียวมีค่าสีหลายร้อยแบบ ด้านที่โดนแสงสว่างกว่า ขอบมืดกว่า โมเดลจึงจำ "แอปเปิล" จากตัวเลขค่าเดียวไม่ได้ ต้องจำจาก รูปแบบ ของตัวเลขรอบ ๆ ซึ่งเป็นงานของ CNN ในบทที่ 5–6
  • เมื่อดูเฉพาะช่อง R แอปเปิลแดงและส้มเป็นสีขาวสว่าง (ค่า R สูง) แต่ในช่อง B ทั้งคู่เป็นสีมืด แต่ละช่องจึงให้ข้อมูลคนละแบบ
  • ตรงขอบระหว่างผลไม้สองลูก ค่าสีจะค่อย ๆ เปลี่ยนจากค่าหนึ่งไปอีกค่าหนึ่ง ในภาพจริงไม่มีเส้นขอบคม ๆ ให้โมเดลเห็น
🤔 ลองคิดก่อน: ภาพขาวดำ (grayscale) ขนาด 640×640 มีตัวเลขกี่ตัว ภาพขาวดำมีช่องเดียว (C = 1) จึงมี 640 × 640 × 1 = 409,600 ตัว น้อยกว่าภาพสีสามเท่า YOLO11 ที่เทรนบน COCO รับภาพ 3 ช่อง ถ้าป้อนภาพขาวดำผ่าน model.predict() ภาพจะถูกอ่านเป็นภาพ 3 ช่องที่ทั้งสามช่องมีค่าเท่ากัน

1.2 Tensor และ shape

Tensor คืออาร์เรย์ของตัวเลขที่มีกี่มิติก็ได้ ตัวเลขตัวเดียวเป็น tensor 0 มิติ รายการตัวเลขเป็น 1 มิติ ตารางเป็น 2 มิติ และตารางหลายชั้นซ้อนกันเป็น 3 มิติ Shape คือการบอกขนาดของแต่ละมิติเป็นทูเพิล (tuple) เช่น (3, 640, 640)

ภาพสีเป็น tensor 3 มิติ แต่เรียงมิติได้สองแบบ

รูปแบบshapeใครใช้อ่านค่าพิกเซล (y, x)
HWC (Height, Width, Channel)(640, 640, 3)ไฟล์ภาพ, OpenCV, NumPy, PILimg[y, x] → ได้ 3 ค่า
CHW (Channel, Height, Width)(3, 640, 640)PyTorch (ซึ่ง YOLO11 ใช้)t[:, y, x] → ได้ 3 ค่า

ข้อควรจำคือ ลำดับในวงเล็บเป็นแถว (y) ก่อนคอลัมน์ (x) เสมอ ภาพกว้าง 1280 สูง 720 จึงมี shape (720, 1280, 3) ไม่ใช่ (1280, 720, 3) คนพูดขนาดภาพเป็น "กว้าง×สูง" แต่ tensor เก็บเป็น "สูง, กว้าง" ความต่างนี้ทำให้เกิดบั๊กบ่อยมาก

ซิมมูเลชั่น 1.4 ภาพสีคือก้อนตัวเลข 3 มิติ

ลองกด "แยก 3 ช่องวางเรียงกัน" แล้วหาแอปเปิลแดงในแต่ละช่อง จากนั้นกด "ซ้อนเป็นก้อน" แล้วลากหมุนดูก้อน (3, 16, 16) จากนั้นกด "อ่านตามลำดับ HWC" กับ "CHW" แล้วเทียบแถบหน่วยความจำด้านล่างว่าเติมสีต่างกันอย่างไร

มุมมอง:

ภาพผลไม้ย่อเหลือ 16 × 16 พิกเซลเพื่อให้นับลูกบาศก์ได้ · 1 ลูกบาศก์ = ตัวเลข 1 ตัว · ลากเพื่อหมุน · คลิกลูกบาศก์เพื่ออ่านค่าและตำแหน่ง

แถบหน่วยความจำ (ตัวเลข 768 ตัวเรียงต่อกันเป็นแถวเดียว แบ่งแสดง 2 บรรทัด)

👀 สิ่งที่ควรสังเกต
  • แยก 3 ช่อง: ในช่อง R แอปเปิลแดงสว่างพอ ๆ กับผนังสีครีม (204 เทียบกับราว 232) แยกกันไม่ออก แต่ในช่อง G แอปเปิลมืด (60) ขณะที่ผนังยังสว่าง (ราว 226) สีแดงจึงเกิดจาก "R มาก G น้อย B น้อย" และต้องดูหลายช่องพร้อมกันจึงจะรู้ว่าเป็นสีอะไร
  • "ซ้อนเป็นก้อน" คือหน้าตาจริงของ tensor (3, 16, 16) แผ่นทั้งสามมีขนาดเท่ากันและวางตรงกันพิกเซลต่อพิกเซล
  • อ่านตามลำดับ HWC: ลูกบาศก์สีเหลืองกระโดด R → G → B ของพิกเซลเดียวกันจนครบ 3 ช่องแล้วค่อยเลื่อนไปพิกเซลถัดไป แถบหน่วยความจำจึงเป็นลาย แดง-เขียว-น้ำเงิน สลับกันถี่ ๆ
  • อ่านตามลำดับ CHW: ไล่แผ่น R จนครบทั้ง 256 ตัวก่อน แล้วจึงไปแผ่น G และ B แถบหน่วยความจำจึงเป็นสามก้อนใหญ่ ตัวเลขชุดเดียวกันทั้งหมด ต่างกันแค่ลำดับ (เหมือนซิม 1.3 แต่เห็นเป็นก้อน)
  • เปิด batch: ได้ 4 ก้อนเรียงกัน shape (4, 3, 16, 16) ทุกก้อนต้องมีขนาดเท่ากันจึงต่อกันเป็น tensor เดียวได้

ทำไม PyTorch ใช้ CHW ในบทที่ 5 คุณจะเห็นว่า convolution ทำงานบน "ระนาบ" H × W ของแต่ละช่อง การเก็บตัวเลขของช่องเดียวกันไว้ติดกันจึงสะดวกต่อการคำนวณ และไลบรารีของ PyTorch ก็ออกแบบให้ใช้ลำดับนี้เป็นค่าเริ่มต้น ซิมมูเลชั่นด้านล่างแสดงว่าตัวเลขชุดเดียวกันถูกวางเรียงในหน่วยความจำต่างกันอย่างไร

ซิมมูเลชั่น 1.3 HWC กับ CHW ในหน่วยความจำ

ลองคลิกพิกเซลในภาพ 4×4 แล้วสังเกตว่าตัวเลข 3 ตัวของพิกเซลนั้นอยู่ติดกันในแบบไหน และกระจายห่างกันในแบบไหน

ภาพ H=4, W=4, C=3

HWC shape (4, 4, 3): ตัวเลข 48 ตัวเรียงต่อกัน แบบ R G B ของพิกเซลแรก แล้ว R G B ของพิกเซลถัดไป …

CHW shape (3, 4, 4): R ทั้ง 16 ตัวก่อน แล้ว G ทั้ง 16 ตัว แล้ว B ทั้ง 16 ตัว

👀 สิ่งที่ควรสังเกต
  • ตัวเลขทั้ง 48 ตัวเป็นชุดเดียวกัน ต่างกันแค่ลำดับ การแปลง HWC → CHW (transpose) จึงไม่ได้เปลี่ยนค่าใดเลย
  • ใน HWC ค่า R, G, B ของพิกเซลเดียวกันอยู่ติดกัน ส่วนใน CHW ค่าของพิกเซลเดียวกันห่างกันทีละ H×W = 16 ตำแหน่ง แต่ค่าช่องเดียวกันของพิกเซลข้างเคียงอยู่ติดกัน
  • ถ้านำตัวเลขแบบ HWC ไปตีความว่าเป็น CHW โดยไม่ transpose จะได้ภาพที่เพี้ยนทั้งภาพ โปรแกรมไม่ error แต่ผลผิด บั๊กแบบนี้จึงหายาก

มิติ batch: (N, C, H, W)

โมเดลรับภาพครั้งละหลายภาพพร้อมกันเพื่อให้ GPU ทำงานได้เต็มที่ การนำภาพหลายภาพที่ shape เท่ากันมาซ้อนกันเรียกว่า batch ซึ่งเพิ่มมิติข้างหน้าอีกหนึ่งมิติเป็น (N, C, H, W) ค่าเริ่มต้นของ batch ตอนเทรนใน Ultralytics คือ 16 จึงได้ tensor (16, 3, 640, 640) ส่วน model.predict() ตั้ง batch = 1 จึงได้ (1, 3, H, W)

ภาพใน batch เดียวกันต้องมี H และ W เท่ากัน เพราะ tensor ต้องเป็นทรงสี่เหลี่ยมเรียบร้อยทุกมิติ ซึ่งเป็นเหตุผลข้อหนึ่งที่ต้องทำ letterbox ในหัวข้อ 1.4

🤔 ลองคิดก่อน: ใน tensor shape (1, 3, 640, 640) ตัวเลขที่ตำแหน่ง [0, 2, 10, 20] คือค่าอะไร ภาพที่ 0 ใน batch, ช่องที่ 2 (นับจาก 0 คือ R=0, G=1, B=2 จึงเป็นช่อง B), แถว y = 10, คอลัมน์ x = 20 แปลว่าเป็นค่าสีน้ำเงินของพิกเซลที่อยู่ห่างจากขอบบน 10 แถวและห่างจากขอบซ้าย 20 คอลัมน์

กับดัก: OpenCV อ่านภาพเป็น BGR

cv2.imread() ของ OpenCV ให้ภาพแบบ HWC ที่เรียงช่องเป็น B, G, R ไม่ใช่ R, G, B ส่วนโมเดล YOLO11 เทรนด้วยภาพ RGB ตัว predictor ของ Ultralytics จึงกลับลำดับช่องก่อนส่งเข้าโมเดล (ดูบรรทัด im[..., ::-1] ในโค้ดหัวข้อ 1.5)

1.3 Normalization

ก่อนเข้าโมเดล ตัวเลข 0–255 จะถูกเปลี่ยนเป็นทศนิยม (float32) ช่วง 0.0–1.0 ด้วยการหารด้วย 255 

x_normalized = x / 255

ตัวอย่าง: 255 → 1.0, 128 → 0.502, 114 → 0.447, 0 → 0.0

เหตุผลคือในบทที่ 2–3 เครือข่ายประสาทเทียมจะนำค่าอินพุตไปคูณกับน้ำหนัก (weight) แล้วปรับน้ำหนักทีละนิดตามความชัน (gradient) การคำนวณนี้เสถียรเมื่ออินพุตมีขนาดเล็กและอยู่ในช่วงที่แน่นอน ถ้าป้อนค่าใหญ่ถึง 255 ผลรวมในชั้นแรก ๆ จะใหญ่ผิดปกติและการเทรนจะแกว่ง และเนื่องจากต้องเก็บค่าที่เป็นเศษส่วนได้ จึงต้องเปลี่ยนชนิดข้อมูลจาก uint8 เป็น float ด้วย

💡 รายละเอียดจากโค้ดจริง
  • Ultralytics หารด้วย 255 อย่างเดียว ไม่ได้ลบค่าเฉลี่ยหรือหารด้วยส่วนเบี่ยงเบนมาตรฐาน (mean/std) แบบที่โมเดลจำแนกภาพหลายตัวทำ
  • ใน predictor.preprocess การหาร 255 เกิดขึ้น เฉพาะเมื่ออินพุตไม่ใช่ torch.Tensor (if not_tensor: im /= 255) ถ้าคุณส่ง tensor เข้า model.predict() เอง ต้อง normalize เป็น 0–1 ให้เรียบร้อยก่อน มิฉะนั้นโมเดลจะเห็นค่าสูงสุดถึง 255 และทำนายผิดทั้งหมด

1.4 Letterbox: ทำให้ทุกภาพมีขนาดที่โมเดลรับได้

ภาพจริงมีหลายขนาด เช่น ภาพจากกล้องแนวนอน 1280×720 หรือภาพจากโทรศัพท์แนวตั้ง 1080×1920 แต่โมเดลมีเงื่อนไขสองข้อ

  1. ขนาดภาพ (imgsz) ค่าเริ่มต้นคือ 640 โมเดลถูกเทรนให้เห็นวัตถุในขนาดประมาณนี้
  2. ด้านกว้างและสูงต้อง หารด้วย 32 ลงตัว เพราะภายในโมเดล ภาพจะถูกย่อครึ่งหนึ่งต่อกัน 5 ครั้ง (25 = 32) ซึ่งจะเห็นในบทที่ 6 และ 9

ทำได้สองวิธี

  • ยืดตรง ๆ (stretch) ย่อหรือขยายให้เป็น 640×640 ทันที ภาพจะบิดสัดส่วน ส้มกลม ๆ กลายเป็นวงรี วัตถุจึงมีรูปทรงไม่เหมือนที่โมเดลเคยเห็นตอนเทรน
  • Letterbox ย่อภาพด้วยอัตราส่วนเดียวกันทั้งแนวกว้างและแนวสูงจนด้านยาวเท่ากับ 640 แล้ว เติมขอบสีเทา (114, 114, 114) ในส่วนที่เหลือ ชื่อนี้มาจากแถบดำบนล่างเวลาดูภาพยนตร์จอกว้างบนทีวีจอเก่า

สูตรจากโค้ดจริง (ultralytics/data/augment.py คลาส LetterBox)

# shape = (H, W) ของภาพต้นฉบับ, new_shape = (640, 640)
r = min(new_shape[0] / shape[0], new_shape[1] / shape[1])   # อัตราส่วนย่อ ใช้ค่าเดียวทั้งสองแกน
new_unpad = round(shape[1] * r), round(shape[0] * r)        # (กว้าง, สูง) หลังย่อ
dw, dh = new_shape[1] - new_unpad[0], new_shape[0] - new_unpad[1]  # ส่วนที่ขาด
if self.auto:                                               # โหมดสี่เหลี่ยมเล็กสุด
    dw, dh = np.mod(dw, self.stride), np.mod(dh, self.stride)   # เติมแค่ให้หาร 32 ลงตัว
dw /= 2; dh /= 2                                            # แบ่งครึ่งไปสองฝั่ง (center=True)
img = cv2.resize(img, new_unpad, interpolation=cv2.INTER_LINEAR)
top, bottom = round(dh - 0.1), round(dh + 0.1)              # ถ้าเป็นเลขคี่ ฝั่งล่าง/ขวาได้มากกว่า 1
left, right = round(dw - 0.1), round(dw + 0.1)
img = cv2.copyMakeBorder(img, top, bottom, left, right, cv2.BORDER_CONSTANT, value=(114, 114, 114))

ตัดมาเฉพาะส่วนสำคัญ ค่าเริ่มต้นใน __init__ คือ auto=False, scaleup=True, center=True, stride=32, padding_value=114

ตัวอย่าง: ภาพ 1280×720

  • r = min(640/720, 640/1280) = min(0.889, 0.5) = 0.5 (ด้านกว้างเป็นตัวจำกัด)
  • ขนาดหลังย่อ = round(1280×0.5) × round(720×0.5) = 640 × 360 สัดส่วนยังเป็น 16:9 เท่าเดิม
  • dw = 640 − 640 = 0, dh = 640 − 360 = 280 → แบ่งครึ่ง: บน 140, ล่าง 140
  • ผลลัพธ์ 640 × 640 โดยมีแถบเทาบนล่างรวม 280 แถว คิดเป็น 43.75% ของพื้นที่ทั้งหมด

แต่ model.predict() ไม่ได้ใช้ 640×640 เสมอไป

แถบเทา 43.75% เป็นการคำนวณที่สูญเปล่า ตอน predict Ultralytics จึงใช้ auto=True ซึ่งเติมขอบเพียงให้ด้านนั้นหารด้วย 32 ลงตัว สำหรับภาพ 1280×720: dh = 280 mod 32 = 24 → บน 12, ล่าง 12 → ได้ 640 × 384

ตรวจจากโค้ดได้ว่าเงื่อนไขอยู่ใน engine/predictor.py เมธอด pre_transform: auto = same_shapes and self.args.rect and (self.model.pt or ...) และ model.predict() ตั้ง rect=True เป็นค่าเริ่มต้น (engine/model.py) ผลคือ ถ้าภาพทุกภาพใน batch มีขนาดเท่ากัน และโมเดลเป็นไฟล์ PyTorch .pt จะได้สี่เหลี่ยมผืนผ้าเล็กที่สุด แต่ถ้าโมเดลถูก export เป็นไฟล์ขนาดคงที่ (เช่น ONNX แบบไม่ dynamic) จะได้ 640×640 เสมอ

🔬 ยืนยันด้วยการรันจริง (ultralytics 8.4.2) เมื่อป้อนภาพ 1280×720 เข้า YOLO("yolo11n-seg.pt").predict(...) Ultralytics พิมพ์ log ว่า 
0: 384x640 (no detections), 84.9ms
Speed: 6.3ms preprocess, 84.9ms inference, 0.9ms postprocess per image at shape (1, 3, 384, 640)
ซึ่งตรงกับที่คำนวณไว้ ส่วนการเทรนและ validation มีขั้นเตรียมภาพของตัวเอง (เช่น mosaic) จะเรียนในบทที่ 11

รายละเอียดเพิ่มเติม: ตอน predict scaleup=True ภาพที่เล็กกว่า 640 จะถูก ขยาย ขึ้น เช่น 500×500 → 640×640 (r = 1.28) และการย่อหรือขยายใช้ cv2.INTER_LINEAR (bilinear) ซึ่งเฉลี่ยสีของพิกเซลข้างเคียง

👀 สิ่งที่ควรสังเกต
  • ขอบเทาเติมด้าน สั้น ของภาพเสมอ ภาพแนวนอนเติมบนล่าง ภาพแนวตั้งเติมซ้ายขวา และแบ่งเท่ากันสองฝั่ง (ถ้าเป็นเลขคี่ ฝั่งล่างหรือขวาได้มากกว่า 1 พิกเซล ลองดู 1000×333)
  • โหมด auto=True ใช้ขอบเทาน้อยกว่ามาก และด้านที่ไม่ใช่ 640 จะเป็นพหุคูณของ 32 เสมอ (384, 480, 224, …)
  • โหมดยืดตรง ๆ ไม่มีขอบเทา แต่ผลไม้กลายเป็นวงรี เทียบตัวเลข rx กับ ry ที่ไม่เท่ากันได้เลย
  • คลิกจุดบนผลไม้ด้านขวา แล้วดูว่าจุดบนภาพต้นฉบับอยู่ที่ผลไม้ลูกเดียวกัน สูตรย้อนกลับคือลบขอบเทาออกแล้วหารด้วย r

ย้อน letterbox: พิกัดผลทำนายกลับสู่ภาพจริง

โมเดลทำนายตำแหน่งวัตถุบน ภาพที่เข้าโมเดล แต่ผู้ใช้ต้องการตำแหน่งบน ภาพต้นฉบับ ขั้นสุดท้ายของ pipeline จึงต้องย้อนกลับด้วยสูตรที่สลับลำดับของ letterbox (ฟังก์ชัน scale_boxes ใน ultralytics/utils/ops.py) 

x_original = (x − left) / r
y_original = (y − top)  / r

ตัวอย่าง: ภาพ 1280×720 ในโหมด 640×640 (r = 0.5, top = 140) จุด (320, 200) บนภาพที่เข้าโมเดลตรงกับ ((320 − 0)/0.5, (200 − 140)/0.5) = (640, 120) บนภาพต้นฉบับ สำหรับ instance segmentation segment/predict.py เรียก scale_boxes กับกล่อง และ mask ก็ต้องผ่านการตัดขอบเทาออกและปรับขนาดกลับในทำนองเดียวกัน (รายละเอียดในบทที่ 10)

1.5 รวมทุกขั้น: เส้นทางของภาพก่อนเข้าโมเดล

นี่คือโค้ดจริงใน ultralytics/engine/predictor.py เมธอด preprocess ตอนนี้คุณอ่านเข้าใจได้ทุกบรรทัดแล้ว 

im = np.stack(self.pre_transform(im))     # letterbox ทุกภาพ แล้วซ้อนเป็น batch: (N, H, W, 3) BGR uint8
if im.shape[-1] == 3:
    im = im[..., ::-1]                    # BGR → RGB (กลับลำดับมิติสุดท้าย)
im = im.transpose((0, 3, 1, 2))           # BHWC → BCHW: (N, 3, H, W)
im = np.ascontiguousarray(im)             # จัดเรียงในหน่วยความจำใหม่ให้ต่อเนื่อง (ดูซิม 1.3)
im = torch.from_numpy(im)
im = im.to(self.device)                   # ย้ายไป GPU ถ้ามี
im = im.half() if self.model.fp16 else im.float()   # uint8 → float
if not_tensor:
    im /= 255                             # 0–255 → 0.0–1.0

import cv2, numpy as np, torch
from ultralytics.utils import ASSETS
from ultralytics.data.augment import LetterBox

img = cv2.imread(str(ASSETS / "bus.jpg"))
print(img.shape, img.dtype)            # (1080, 810, 3) uint8
print("BGR:", img[100, 200], "RGB:", img[100, 200][::-1])

lb = LetterBox(640, auto=True, stride=32)(image=img)
print(lb.shape)                        # (640, 480, 3)

x = lb[None][..., ::-1].transpose(0, 3, 1, 2)       # batch, BGR→RGB, BCHW
x = torch.from_numpy(np.ascontiguousarray(x)).float() / 255
print(x.shape, x.min().item(), x.max().item())      # torch.Size([1, 3, 640, 480]) 0.0 1.0
print(x.numel())                                    # 921600

🔗 อยู่ตรงไหนใน YOLO11-seg

บทนี้อยู่ที่ ต้นทางสุด ของ pipeline ได้แก่การเปลี่ยนไฟล์ภาพเป็น tensor (1, 3, H, W) ค่า 0–1 ด้วย letterbox และอยู่ที่ ปลายทางสุด ด้วย เพราะกล่องและ mask ที่โมเดลทำนายบนภาพ letterbox ต้องถูก "ย้อน letterbox" กลับไปเป็นพิกัดบนภาพจริง ทุกอย่างระหว่างสองจุดนี้ (Backbone → NMS) คือการคำนวณกับ tensor ที่ได้จากบทนี้

สรุปท้ายบท

  • ภาพสีคือตัวเลข 3 ตัวต่อพิกเซล (R, G, B) แต่ละตัวมีค่า 0–255 (uint8) ภาพ 640×640 มี 1,228,800 ตัวเลข
  • Tensor ภาพมีสองรูปแบบ: HWC (H, W, 3) ของไฟล์ภาพ/OpenCV และ CHW (3, H, W) ของ PyTorch โดยเขียน สูง ก่อน กว้าง เสมอ
  • หลายภาพซ้อนเป็น batch (N, C, H, W) ซึ่งต้องมีขนาดภาพเท่ากัน
  • OpenCV อ่านเป็น BGR ส่วน Ultralytics กลับเป็น RGB ด้วย im[..., ::-1]
  • Normalization ของ Ultralytics คือหาร 255 อย่างเดียว ได้ float 0.0–1.0 (และไม่ทำให้ถ้าอินพุตเป็น tensor อยู่แล้ว)
  • Letterbox ย่อด้วย r = min(640/H, 640/W) ทั้งสองแกน แล้วเติมขอบเทา 114 แบ่งครึ่งสองฝั่ง วัตถุจึงไม่บิดสัดส่วน
  • model.predict() กับไฟล์ .pt ใช้ auto=True เติมขอบแค่ให้หาร 32 ลงตัว (1280×720 → 640×384) และพิกัดผลลัพธ์ย้อนกลับด้วย (x − pad)/r
