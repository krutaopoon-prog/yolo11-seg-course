บทที่ 4 การเทรนเครือข่าย: Backpropagation และ Overfitting

gradient ของทุก weight มาจากไหน, ข้อมูลถูกป้อนเป็นรอบ ๆ อย่างไร และทำไม "เก่งตอนเทรน" ไม่ได้แปลว่า "เก่งจริง"

🎯 วัตถุประสงค์การเรียนรู้ เมื่อจบบทนี้ คุณควรทำสิ่งต่อไปนี้ได้
  1. อธิบาย forward pass และ backward pass ได้ และใช้กฎลูกโซ่ (chain rule) หา gradient บนกราฟการคำนวณเล็ก ๆ ได้
  2. อธิบายความหมายของ epoch, batch, iteration และคำนวณจำนวน iteration ต่อ epoch ได้
  3. อธิบายหน้าที่ของชุด train / validation / test และอ่านสัญญาณ overfitting กับ underfitting จากกราฟ loss ได้
  4. อธิบายว่า data augmentation และ transfer learning ช่วยลด overfitting ได้อย่างไร และบอกความต่างระหว่างเริ่มเทรนจาก yolo11n-seg.pt กับ yolo11n-seg.yaml ได้
  5. อธิบายว่า data leakage คืออะไร เกิดจากอะไร และแบ่งข้อมูลอย่างไรจึงจะไม่รั่ว

ทบทวนความรู้เดิม

ในบทที่ 3 คุณเห็นว่าการเทรนก็คือการทำซ้ำสูตร w ← w − η · ∂L/∂w และในซิม 3.4 นิวรอนตัวเดียวก็ปรับ w₁, w₂, b เองจนแยกพิกเซลแอปเปิลได้ นิวรอนตัวนั้นมี weight แค่ 3 ตัว จึงเขียนสูตรความชันของแต่ละตัวได้ตรง ๆ แต่ yolo11n-seg มีนิวรอนต่อกันเป็นร้อยชั้น และมี weight 2,876,848 ตัว คำถามแรกของบทนี้คือ จะหา ∂L/∂w ของทุกตัวได้อย่างไรในเวลาอันสั้น คำตอบคือ backpropagation คำถามที่สองคือ เมื่อ loss ลดลงแล้ว เราจะรู้ได้อย่างไรว่าโมเดลเก่งจริง ไม่ได้แค่จำข้อสอบ

4.1 Forward pass และ Backward pass

เครือข่ายประสาทเทียมคือการคำนวณย่อย ๆ ต่อกันเป็นสาย เช่น คูณ, บวก, ผ่าน SiLU, คูณ, บวก, แล้วเทียบกับเฉลย ถ้าวาดแต่ละขั้นเป็นโหนดแล้วโยงด้วยลูกศร จะได้ กราฟการคำนวณ (computational graph)

  • Forward pass (ขาไป): ป้อนข้อมูลทางซ้าย แล้วคำนวณไปทางขวาทีละโหนดจนได้คำทำนาย และได้ loss ที่ปลายทาง
  • Backward pass (ขากลับ): เริ่มจาก loss แล้วย้อนไปทางซ้ายทีละโหนด เพื่อหาว่า "ถ้าค่านี้ขยับนิดหนึ่ง loss จะขยับกี่เท่า" ของทุกค่าในกราฟ การย้อนกลับแบบนี้เรียกว่า backpropagation [Rumelhart1986]

กฎลูกโซ่: คูณความชันต่อกันไปตามทาง

ลองนึกถึงเฟืองที่ต่อกันเป็นทอด ๆ ถ้าหมุนเฟืองแรก 1 รอบแล้วเฟืองที่สองหมุน 3 รอบ และเฟืองที่สองหมุน 1 รอบแล้วเฟืองที่สามหมุน 2 รอบ แปลว่าหมุนเฟืองแรก 1 รอบ เฟืองที่สามจะหมุน 3 × 2 = 6 รอบ กฎลูกโซ่ก็คือแบบนี้ ความชันจาก w ไปถึง L เท่ากับ ผลคูณของความชันเฉพาะที่ (local slope) ของทุกโหนดที่อยู่ระหว่างทาง 

u = w·x  →  ŷ = u + b  →  L = (ŷ − y)²

∂L/∂w  =  ∂L/∂ŷ   ×  ∂ŷ/∂u  ×  ∂u/∂w
       =  2(ŷ − y) ×    1     ×    x

แต่ละโหนดต้องรู้แค่ความชันของตัวเอง เช่น โหนด "+b" รู้ว่าอินพุตขยับเท่าไหร่ เอาต์พุตก็ขยับเท่านั้น (ความชัน 1) ส่วนโหนด "×w" รู้ว่าถ้า w ขยับ 1 หน่วย เอาต์พุตจะขยับ x หน่วย backward pass จึงทำได้ง่ายมาก คือส่งตัวเลขย้อนกลับมาทีละโหนด แล้วแต่ละโหนดคูณความชันของตัวเองเข้าไปก่อนส่งต่อ ลองกดดูในซิมด้านล่าง

ซิมมูเลชั่น 4.1 กราฟคำนวณ: ตัวเลขไหลไปข้างหน้า gradient ไหลย้อนกลับ

ลองกด "เดินหน้า" จนได้ L แล้วกด "ย้อนกลับ" ทีละโหนด สังเกตว่าตัวเลขสีแดงแต่ละตัวเกิดจากการคูณอะไรกับอะไร จากนั้นกด "ปรับ weight 1 ก้าว" แล้วดูว่า L ลดลงหรือไม่

เครือข่าย:

สีน้ำเงิน = ค่าจาก forward pass · สีแดง = gradient จาก backward pass (ถ้าค่านี้เพิ่ม 1 หน่วยเล็ก ๆ L จะเปลี่ยนกี่เท่า) · x กับ y คือพิกเซลและเฉลย จึงไม่ถูกปรับ

👀 สิ่งที่ควรสังเกต
  • ตัวเลขสีแดงทุกตัวได้จาก "ตัวเลขสีแดงที่อยู่ทางขวา × ความชันเฉพาะที่ของโหนด" ไม่มีโหนดไหนต้องรู้สูตรทั้งสาย
  • นิวรอน 1 ตัว: L = 0.25, ∂L/∂w = −0.8 และ ∂L/∂b = −1 (ติดลบทั้งคู่ แปลว่าควรเพิ่ม w และ b) พอปรับ 1 ก้าว L ลดเหลือราว 0.113
  • gradient ของ b (−1) ใหญ่กว่าของ w (−0.8) เพราะ w ต้องคูณ x = 0.8 อีกที ความชันจึงขึ้นกับค่าของข้อมูลที่ไหลผ่านด้วย
  • เมื่อย้อนกลับครบแล้ว กล่องผลลัพธ์จะลอง "ขยับ w จริง ๆ 0.001" แล้ววัดว่า L เปลี่ยนเท่าไร ผลหารที่ได้ตรงกับ gradient จาก backpropagation แทบทุกหลัก
  • 2 ชั้น: gradient ที่ส่งกลับมาถึง h ไม่ได้ใช้ปรับ h (h ไม่ใช่ weight) แต่ถูก "ส่งต่อ" ผ่าน SiLU ไปให้ w₁, b₁ ในชั้นแรก นี่คือหัวใจของการเทรนเครือข่ายหลายชั้น

ทำไม backpropagation จึงเร็ว

ถ้าจะหา ∂L/∂w ด้วยการ "ขยับ w ทีละตัวแล้ววัด L ใหม่" แบบที่ซิมใช้ตรวจคำตอบ จะต้องคำนวณ forward ใหม่ 2,876,848 รอบต่อการปรับหนึ่งครั้ง ส่วน backpropagation เดินย้อนกลับ รอบเดียว แล้วใช้ตัวเลขสีแดงของโหนดทางขวาซ้ำสำหรับทุกโหนดทางซ้าย จึงได้ gradient ของทุก weight พร้อมกัน ใช้เวลาเพียงประมาณ 2 เท่าของ forward pass หนึ่งรอบ

ในทางปฏิบัติไม่มีใครเขียน backward เอง ไลบรารี PyTorch จดกราฟการคำนวณไว้ระหว่าง forward แล้วคำนวณขากลับให้ทั้งหมดด้วยคำสั่งเดียว ใน engine/trainer.py ของ Ultralytics วงจรเทรนทุก iteration มีสามจังหวะ คือ forward ได้ loss → backward() → optimizer_step() ซึ่งก็คือสามขั้นในซิมด้านบน

💡 ผลคูณยาว ๆ มีปัญหาของมัน gradient ของชั้นแรก ๆ คือผลคูณของความชันจากทุกชั้นที่อยู่ระหว่างทาง ถ้าแต่ละชั้นมีความชันน้อยกว่า 1 เช่น 0.5 ต่อกัน 30 ชั้น จะเหลือ 0.5³⁰ ≈ 0.000000001 ชั้นแรก ๆ แทบไม่ได้เรียนรู้ ปัญหานี้เรียกว่า vanishing gradient เครือข่ายสมัยใหม่อย่าง YOLO11 แก้ด้วย activation ที่ความชันไม่หดเร็ว (SiLU), BatchNorm และ "ทางลัด" (residual connection) ซึ่งจะเรียนในบทที่ 6

4.2 Epoch, Batch และ Iteration

การเทรนจริงไม่ได้คำนวณ loss จากภาพทั้งชุดในครั้งเดียว เพราะหน่วยความจำไม่พอ แต่จะแบ่งภาพเป็นกลุ่มเล็ก ๆ

คำความหมาย
batchกลุ่มภาพที่ป้อนเข้าโมเดลพร้อมกัน loss ของ batch คือค่าเฉลี่ยของภาพในกลุ่ม ขนาดกลุ่มเรียกว่า batch size
iterationการทำงาน 1 รอบกับ 1 batch: forward → loss → backward (→ ปรับ weight)
epochป้อนภาพในชุดเทรน ครบทุกภาพ 1 รอบ แต่ละ epoch จะสุ่มลำดับภาพใหม่ ภาพจึงไปอยู่คนละ batch กับรอบก่อน
iteration ต่อ epoch = ⌈ จำนวนภาพ / batch size ⌉        (⌈ ⌉ = ปัดขึ้น)
ตัวอย่าง: 1,000 ภาพ, batch 16 → 1000/16 = 62.5 → 63 iteration (batch สุดท้ายมี 8 ภาพ)

การคำนวณ gradient จาก batch เล็ก ๆ แทนที่จะใช้ทั้งชุด คือที่มาของคำว่า stochastic ใน SGD (บทที่ 3) ทิศที่ได้แต่ละครั้งแกว่งไปบ้างเพราะขึ้นกับว่าสุ่มได้ภาพไหน แต่โดยเฉลี่ยชี้ไปทางเดียวกับ gradient ของทั้งชุด และเร็วกว่ามาก

ซิมมูเลชั่น 4.2 เครื่องคิดเลข iteration

ลองเปลี่ยน batch size ระหว่าง 8, 16, 32 แล้วสังเกตจำนวนกลุ่มสีในแต่ละแถว จากนั้นลองชุดข้อมูลตัวอย่างอื่นแล้วดูว่า Ultralytics เลือก optimizer ตัวไหน

ตัวอย่าง:
👀 สิ่งที่ควรสังเกต
  • แต่ละแถวคือ 1 epoch แต่ละกลุ่มสีคือ 1 batch = 1 iteration ภาพที่ขอบดำคือภาพหมายเลข 1 ภาพเดิม ซึ่งไปอยู่คนละ batch ในแต่ละ epoch เพราะมีการสุ่มลำดับใหม่ทุกรอบ
  • 50 ภาพ, batch 16 → 4 iteration ต่อ epoch โดย batch สุดท้ายมีแค่ 2 ภาพ Ultralytics ไม่ทิ้ง batch ที่ไม่เต็ม (ยกเว้นเมื่อเปิด compile)
  • coco8-seg มี 4 ภาพ batch 16 จึงได้แค่ 1 iteration ต่อ epoch เทรน 30 epoch ก็ได้ 30 iteration และทั้งหมดยังอยู่ในช่วง warmup (100 iteration แรก)
  • COCO train2017 (118,287 ภาพ) 100 epoch มีมากกว่า 10,000 ก้าว Ultralytics จึงเลือก SGD lr 0.01 ส่วนชุดผลไม้ 1,000 ภาพได้ MuSGD (ตามตารางในบทที่ 3)
💡 ใน Ultralytics: 1 iteration ไม่จำเป็นต้องปรับ weight 1 ครั้ง Ultralytics มีค่า nbs = 64 (nominal batch size) ถ้าตั้ง batch = 16 มันจะ สะสม gradient จาก 4 batch (16 × 4 = 64 ภาพ) แล้วค่อยปรับ weight ครั้งเดียว เรียกว่า gradient accumulation ผลคือการปรับแต่ละครั้งใช้ข้อมูลราว 64 ภาพเสมอ ไม่ว่าจะตั้ง batch เท่าไร (ช่วง warmup ช่วงแรกจะค่อย ๆ เพิ่มจำนวนที่สะสมจาก 1 ขึ้นไป)

4.3 Train, Validation และ Test

ลองนึกถึงนักเรียนเตรียมสอบ ถ้าวัดความเก่งด้วยแบบฝึกหัดที่ทำมาแล้วพร้อมเฉลย คะแนนย่อมสูงเกินจริง เพราะนักเรียนอาจ จำเฉลย ได้โดยไม่เข้าใจ โมเดลก็เป็นแบบเดียวกัน จึงต้องแบ่งข้อมูลเป็น 3 ชุดที่ไม่ซ้ำกัน

  • Train: โมเดลเห็นทั้งภาพและเฉลย และใช้ปรับ weight
  • Validation (val): ใช้วัดผลระหว่างเทรน เพื่อเลือกว่า epoch ไหนดีที่สุดและเปรียบเทียบการตั้งค่าต่าง ๆ เช่น learning rate หรือขนาดรุ่น ข้อมูลชุดนี้ไม่ได้ใช้ปรับ weight โดยตรง แต่เรา "ปรับการตัดสินใจ" ตามมัน คะแนนจึงเริ่มเข้าข้างชุดนี้บ้าง
  • Test: เก็บไว้ไม่แตะเลยจนตัดสินใจทุกอย่างเสร็จ แล้ววัดครั้งเดียวเพื่อรายงานผล นี่คือคะแนนที่ใกล้เคียงการใช้งานจริงที่สุด
💡 ใน Ultralytics ไฟล์ data.yaml ระบุโฟลเดอร์ train:, val: และ test: (ไม่บังคับ) ค่าเริ่มต้น val=True จะวัดผลกับชุด val ทุก epoch แล้วบันทึกน้ำหนักของ epoch ที่ดีที่สุดเป็น best.pt (และ epoch ล่าสุดเป็น last.pt) คำว่า "ดีที่สุด" ใน 8.4.2 วัดด้วยค่า fitness ซึ่งสำหรับงาน segmentation คือ mAP50-95 ของกล่อง + mAP50-95 ของ mask (บทที่ 8) ส่วน coco8-seg มีภาพ train 4 ภาพ val 4 ภาพ และไม่มี test

4.4 Overfitting และ Underfitting

Overfitting คือโมเดลจำรายละเอียดของชุดเทรน รวมถึงสัญญาณรบกวน (noise) จนทำนายชุดเทรนได้เกือบสมบูรณ์ แต่ทำนายข้อมูลใหม่ได้แย่ ส่วน underfitting คือโมเดลเรียบง่ายเกินไปจนจับแม้แต่รูปแบบหลักของข้อมูลไม่ได้ ผิดทั้งชุดเทรนและชุดใหม่ ซิมด้านล่างสร้างข้อมูลจากเส้นโค้งที่รู้คำตอบ (เส้นประสีเทา) แล้วเติม noise และให้โมเดลพหุนามที่ซับซ้อนต่างกันมาฟิต

ซิมมูเลชั่น 4.3 ความซับซ้อนของโมเดล: น้อยไป พอดี มากไป

ลองเลื่อน degree จาก 1 ไปถึง 11 แล้วสังเกตว่าเส้น train error (น้ำเงิน) ลดลงตลอด แต่เส้น val error (ส้ม) ลดลงแล้วกลับขึ้น จากนั้นเปลี่ยนเป็น 40 จุดแล้วลองใหม่

จำนวนข้อมูลเทรน:

● จุดดำ = train · ○ จุดส้ม = val (โมเดลไม่เคยเห็น) · เส้นน้ำเงิน = โมเดล

👀 สิ่งที่ควรสังเกต
  • degree 0–1 (เส้นตรง) เป็น underfitting: error สูงทั้ง train และ val เพราะเส้นตรงงอตามเส้นโค้งไม่ได้
  • degree 3–4 พอดี (12 จุด): val error ต่ำสุดราว 0.078 ใกล้กับระดับ noise ที่ใส่ไว้ (0.25² = 0.0625) ซึ่งเป็นค่าต่ำสุดที่เป็นไปได้ เพราะ noise คาดเดาไม่ได้
  • 12 จุด degree 5 ขึ้นไป: train error ยังลดต่อ แต่ val error กลับสูงขึ้น 2–5 เท่า และที่ degree 9–11 สูงกว่าจุดดีที่สุด 13–38 เท่า degree 11 มีค่าให้ปรับ 12 ตัวเท่าจำนวนจุด เส้นจึงผ่านจุดเทรน ทุกจุด (train error ≈ 0) แต่สะบัดแรงระหว่างจุด นี่คือ overfitting โมเดลจำ noise แทนที่จะเรียนรูปร่างจริง
  • 40 จุด: degree 3 ถึง 11 ได้ val error ใกล้เคียงกันหมด แม้ degree 11 ก็สูงกว่าจุดดีที่สุดเพียงราว 1.1 เท่า เพราะจุดที่หนาแน่นไม่เปิดช่องให้เส้นสะบัด ข้อมูลมากขึ้นคือยาแก้ overfitting ที่ดีที่สุด

สัญญาณบนกราฟตอนเทรนจริง

ตอนเทรนเครือข่ายจริงเราไม่ได้เปลี่ยน degree แต่โมเดลค่อย ๆ "ซับซ้อนขึ้น" ตามจำนวน epoch: ช่วงแรกจับรูปแบบหลัก ช่วงหลังเริ่มจำรายละเอียดยิบย่อยของชุดเทรน สัญญาณ overfitting จึงเห็นได้บนกราฟ loss ตามเวลา ซิมด้านล่างเทรนเครือข่าย 1 ชั้นซ่อน (40 นิวรอน, SiLU, Adam) ด้วย backpropagation กับข้อมูลชุดเดียวกับซิม 4.3

ซิมมูเลชั่น 4.4 กราฟ loss ตามเวลาเทรน และ best.pt

ลองกด "เทรน" กับข้อมูล 12 จุดแล้วสังเกตจุดที่ val loss ต่ำสุด (เส้นเขียว) เทียบกับตอนจบ จากนั้นเปิด early stopping แล้วเทรนใหม่ และลองกับ 40 จุด

จำนวนข้อมูลเทรน:
👀 สิ่งที่ควรสังเกต
  • 12 จุด: ช่วงแรก train loss และ val loss ลดลงพร้อมกัน (โมเดลเรียนรูปร่างหลัก) จากนั้น train loss ยังลดต่อจาก 0.065 เหลือ 0.004 แต่ val loss กลับเพิ่มจาก 0.089 เป็น 0.23 เส้นโค้งเริ่มคดเคี้ยวเพื่อผ่านจุดเทรนให้ได้มากที่สุด
  • เส้นแนวตั้งสีเขียวคือ epoch ที่ val loss ต่ำสุด ซึ่งเกิดขึ้นเร็วมาก (epoch 330 จาก 4,000) Ultralytics เก็บน้ำหนัก ณ จุดแบบนี้เป็น best.pt แม้จะเทรนต่อไปจนจบ
  • เปิด early stopping (12 จุด): การเทรนหยุดเองที่ epoch 630 หลังจาก val loss ไม่ดีขึ้นติดกัน 300 epoch ประหยัดเวลาได้ราว 84% โดยไม่เสียโมเดลที่ดีที่สุด (Ultralytics ใช้ patience = 100 epoch)
  • 40 จุด: val loss ไม่กลับขึ้นเลยจนจบ 4,000 epoch (ราว 0.080 ตลอดช่วงหลัง) และเส้นโค้งที่ได้ใกล้เส้นจริงกว่ามาก ถ้าเปิด early stopping จะหยุดราว epoch 1,490 เพราะ val loss แทบไม่เปลี่ยนแล้ว ไม่ใช่เพราะแย่ลง

4.5 Data Augmentation: สร้างข้อมูลใหม่จากข้อมูลเดิม

เมื่อข้อมูลมากขึ้นช่วยลด overfitting ได้ดีที่สุด แต่การหาภาพและวาดเฉลยเพิ่มมีต้นทุนสูง วิธีที่ถูกกว่าคือ data augmentation คือดัดแปลงภาพเดิมแบบสุ่มทุกครั้งที่ป้อนเข้าโมเดล เช่น กลับซ้ายขวา ย่อขยาย เลื่อน ปรับสีและความสว่าง แอปเปิลที่ถูกกลับซ้ายขวาก็ยังเป็นแอปเปิล โมเดลจึงต้องเรียน "ความเป็นแอปเปิล" แทนที่จะจำว่าแอปเปิลอยู่ตรงพิกเซลไหน

  • เฉลยต้องเปลี่ยนตามภาพเสมอ: ถ้าภาพถูกกลับซ้ายขวา กรอบและ polygon ของวัตถุก็ต้องกลับด้วย
  • ทำกับ ชุด train เท่านั้น ใน source ของ Ultralytics ชุด val ถูกสร้างด้วย augment=False (ใช้แค่ letterbox)
  • ภาพเดิมแต่ละภาพจึงหน้าตาไม่ซ้ำกันเลยในแต่ละ epoch

  • ภาพทั้ง 7 มาจากภาพเดียวกับเฉลยชุดเดียวกัน แต่สำหรับโมเดลแล้วตัวเลขพิกเซลต่างกันทั้งหมด

4.6 Transfer Learning: ไม่ต้องเริ่มจากศูนย์

การเทรนโมเดลจากค่าสุ่มต้องใช้ภาพจำนวนมหาศาล แต่ความรู้ระดับล่าง เช่น ขอบ มุม พื้นผิว รูปทรงกลม ใช้ได้กับภาพแทบทุกประเภท Transfer learning คือการเริ่มจาก weight ที่เทรนกับชุดข้อมูลใหญ่มาแล้ว แล้วเทรนต่อกับข้อมูลของเรา (เรียกว่า fine-tuning)

4.7 Data Leakage: ข้อสอบรั่ว

Data leakage คือการที่ข้อมูลในชุด val หรือ test "รั่ว" ไปอยู่ในชุด train ทั้งตรง ๆ หรือในรูปที่เกือบเหมือนกัน ผลคือคะแนน val สูงเกินจริง เราเชื่อว่าโมเดลเก่ง แต่พอใช้งานจริงกับภาพใหม่กลับแย่

สาเหตุที่พบบ่อยในงานภาพ

  • เฟรมวิดีโอหรือภาพถ่ายต่อเนื่อง: เฟรมที่ติดกันแทบเหมือนกันทุกพิกเซล ถ้าสุ่มแบ่งทีละภาพ เฟรมที่ 37 อาจอยู่ใน val ขณะที่เฟรม 36 และ 38 อยู่ใน train
  • วัตถุชิ้นเดียวกันถ่ายหลายมุม หรือภาพซ้ำที่ถูกบันทึกหลายไฟล์
  • ทำ augmentation ก่อนแบ่งชุด: ภาพที่กลับซ้ายขวาไปอยู่ใน train แต่ภาพต้นฉบับไปอยู่ใน val
  • ใช้ pretrained ที่เคยเห็นภาพ val แบบกรณี coco8-seg ด้านบน

ซิมมูเลชั่น 4.6 แบ่งภาพจากวิดีโอ 100 เฟรม

ลองเลือกวิธีแบ่งทีละแบบ แล้วนับกรอบสีแดง (ภาพ val ที่มีภาพเกือบซ้ำอยู่ใน train) คลิกที่ภาพ val เพื่อดูคู่ที่เกือบซ้ำกัน

วิธีแบ่ง:

ภาพจากกล้องที่ค่อย ๆ แพนผ่าน 10 ฉาก (แถบสีใต้ภาพบอกว่าเป็นฉากไหน) ถือว่า "เกือบซ้ำ" เมื่ออยู่ฉากเดียวกันและห่างกันไม่เกิน 3 เฟรม · train val ปลอดภัย val รั่ว

👀 สิ่งที่ควรสังเกต
  • สุ่มทีละภาพ: ภาพ val ทั้ง 20 ภาพมีเพื่อนบ้านที่ห่างไม่เกิน 3 เฟรมอยู่ใน train (ลองกดสุ่มใหม่ก็ยัง 20/20) โมเดลที่จำภาพเทรนได้จะตอบ val ถูกเหมือนลอกข้อสอบ คะแนน val จึงบอกอะไรไม่ได้เลย
  • แบ่งเป็นช่วง: รั่วแค่ 3 ภาพตรงรอยต่อ (เฟรม 80–82 อยู่ฉากเดียวกับเฟรม 79 ที่อยู่ใน train) ดีกว่ามาก แต่ยังไม่ศูนย์
  • แบ่งตามฉาก: ทุกเฟรมของฉากเดียวกันอยู่ชุดเดียวกัน รั่ว 0 ภาพเสมอ ไม่ว่าจะสุ่มใหม่กี่ครั้ง นี่คือวิธีที่ถูกต้อง (เรียกว่า group split)
💡 หลักป้องกัน data leakage
  1. แบ่งชุดข้อมูล ก่อน ทำอย่างอื่นทั้งหมด และแบ่งตาม "กลุ่ม" ที่ภาพในกลุ่มคล้ายกัน เช่น วิดีโอ, วันที่ถ่าย, สถานที่, วัตถุชิ้นเดียวกัน
  2. ตรวจหาและลบภาพซ้ำหรือเกือบซ้ำข้ามชุด
  3. ถ้าคะแนน val สูงผิดปกติ ให้สงสัยไว้ก่อน แล้วลองทดสอบกับภาพที่ถ่ายใหม่จริง ๆ

🔗 อยู่ตรงไหนใน YOLO11-seg

เนื้อหาบทนี้คือทุกอย่างที่เกิดขึ้นเมื่อสั่ง model.train(...) การแบ่ง train/val/test และ augmentation เกิดที่ขั้นภาพก่อนเข้าโมเดล (augmentation ทำร่วมกับ letterbox) จากนั้นทุก iteration ภาพหนึ่ง batch วิ่ง forward ผ่าน Backbone → Neck → Head ได้ loss แล้ว backpropagation ส่ง gradient ย้อนกลับผ่าน Head → Neck → Backbone เพื่อปรับ weight ทุกตัว ส่วนการเลือกว่าจะเริ่มจาก .pt หรือ .yaml คือการเลือกค่าเริ่มต้นของ weight ทุกตัวในสามส่วนนี้

สรุปท้ายบท

  • Forward pass คำนวณจากซ้ายไปขวาจนได้ loss ส่วน backward pass (backpropagation) ส่ง gradient ย้อนกลับ โดยแต่ละโหนดคูณความชันเฉพาะที่ของตัวเอง (กฎลูกโซ่) จึงได้ gradient ของทุก weight ในการย้อนรอบเดียว
  • iteration ต่อ epoch = ⌈จำนวนภาพ / batch⌉ และทุก epoch จะสุ่มลำดับใหม่ Ultralytics สะสม gradient ให้ครบราว 64 ภาพ (nbs) ก่อนปรับ weight
  • Train ใช้ปรับ weight, val ใช้เลือก epoch ที่ดีที่สุดและตั้งค่า (Ultralytics บันทึกเป็น best.pt), test ใช้วัดครั้งเดียวตอนจบ
  • Overfitting: train loss ลดต่อแต่ val loss เพิ่ม เพราะโมเดลจำ noise ส่วน underfitting: ทั้งสองสูง
  • แก้ overfitting ด้วยข้อมูลเพิ่ม, augmentation (ทำเฉพาะ train และเฉลยต้องเปลี่ยนตาม), pretrained weight และ early stopping
  • เริ่มจาก yolo11n-seg.pt ได้ความรู้จาก COCO มาเกือบทั้งหมด (งาน 3 คลาสโอนได้ 98.4% ของ parameter ยกเว้นสาขาคลาสของ Head) ส่วน .yaml เริ่มจากสุ่ม
  • Data leakage ทำให้คะแนนสูงเกินจริง ป้องกันด้วยการแบ่งตามกลุ่ม (เช่น ตามวิดีโอหรือฉาก) ก่อนทำอย่างอื่น
